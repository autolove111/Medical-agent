### **模型加载器（ModelLoader）**

**文件**：\`python\_service/harness/llm\_core/model\_loader\.py\`

#### **设计模式**

采用 **单例模式 \+ 双重检查锁（DCL） \+ 懒加载**：

- **单例**：全局唯一实例，通过 \`ModelLoader\.init\(config\)\` 初始化，后续 \`ModelLoader\(\)\` 返回同一实例
- **DCL**：\`threading\.Lock\` 保证线程安全，避免并发场景下重复加载
- **懒加载**：模型不在构造时加载，而是在首次访问 \`model\` 或 \`tokenizer\` 属性时触发

#### **ModelConfig 数据类**

```Python
@dataclass
class ModelConfig:
    model_path: str              # 本地模型目录路径
    use_4bit: bool = True        # 启用 4-bit 量化
    quant_type: str = "nf4"      # 量化类型
    use_double_quant: bool = True # 双重量化
    temperature: float = 0.7     # 生成温度
    max_new_tokens: int = 2000   # 最大生成 token 数
```

#### **加载流程**

```Plain
ModelLoader.init(config)
    │
    ├─ 重置 _instance = None
    └─ 创建新实例 → ModelLoader(config)
                        │
                        └─ 首次访问 .model / .tokenizer
                            │
                            └─ load()
                                │
                                ├─ 1. 快速检查（无锁）：已加载则直接返回
                                │
                                ├─ 2. 加锁 + 二次检查：防止并发重复加载
                                │
                                ├─ 3. 解析量化配置 _resolve_quantization_config()
                                │       ├─ use_4bit=False → None（不量化）
                                │       ├─ CUDA 不可用 → 警告 + None
                                │       ├─ bitsandbytes 未安装 → 警告 + None
                                │       └─ 正常 → BitsAndBytesConfig(
                                │               load_in_4bit=True,
                                │               bnb_4bit_quant_type="nf4",
                                │               bnb_4bit_use_double_quant=True,
                                │               bnb_4bit_compute_dtype=torch.float16
                                │           )
                                │
                                ├─ 4. 加载分词器
                                │       AutoTokenizer.from_pretrained(
                                │           path, trust_remote_code=True,
                                │           local_files_only=True
                                │       )
                                │
                                ├─ 5. 构建模型参数
                                │       ├─ 有量化: quantization_config + device_map={"": 0}
                                │       └─ 无量化: torch_dtype=float16(GPU)/float32(CPU)
                                │               + device_map="auto"/None
                                │
                                ├─ 6. 加载模型
                                │       AutoModelForCausalLM.from_pretrained(path, **kwargs)
                                │
                                ├─ 7. CPU 回退（无量化且无 GPU 时）
                                │       model.to("cpu")
                                │
                                ├─ 8. 切换推理模式
                                │       model.eval()
                                │
                                └─ 9. 写入类变量 _tokenizer / _model
```

#### **量化回退链**

```Plain
4-bit 量化 (bitsandbytes NF4)
    │
    ├─ CUDA 可用 + bitsandbytes 已安装 → 正常 4-bit 量化
    │
    ├─ CUDA 不可用 → 回退到 fp32 CPU 推理
    │
    └─ bitsandbytes 未安装 → 回退到 fp16（GPU）或 fp32（CPU）
```

### **推理适配器（ChatModel）**

**文件**：\`python\_service/harness/llm\_adapter/chat\_model\.py\`

#### **设计原则**

**零框架依赖**：仅依赖 \`torch\` 和 \`transformers\`，不依赖 LangChain/LangGraph。接收组装好的 prompt 字符串，执行推理，返回文本。

#### **核心能力**

| 方法                 | 说明                                   |
| -------------------- | -------------------------------------- |
| `invoke\(prompt\)` | 同步推理，返回完整文本                 |
| `stream\(prompt\)` | 流式推理，逐 token 返回 `Chunk` 对象 |

#### **invoke 同步流程**

```Plain
invoke(prompt)
    │
    ├─ 1. _build_inputs(prompt)
    │       tokenize → tensor → 移至 CUDA:0（如可用）
    │
    ├─ 2. model.generate() （torch.inference_mode 下）
    │       参数: max_new_tokens, do_sample, temperature, pad_token_id, eos_token_id
    │
    ├─ 3. 切片输出：去掉 prompt 部分，仅保留生成的 token
    │
    ├─ 4. 解码 → strip → 修复乱码 → 截断角色标记
    │
    └─ 5. 返回干净文本
```

#### **stream 流式流程**

```Plain
stream(prompt)
    │
    ├─ 1. _build_inputs(prompt)
    │
    ├─ 2. 创建 TextIteratorStreamer（skip_prompt=True, skip_special_tokens=True）
    │
    ├─ 3. 在守护线程中启动 model.generate(streamer=streamer)
    │
    ├─ 4. 主线程迭代 streamer tokens:
    │       ├─ 修复乱码
    │       ├─ 检测角色标记 → 如发现则截断并返回
    │       └─ 尾部 32 字符缓冲区处理边界 token
    │
    └─ 5. yield 剩余文本
```

采用 **生产者\-消费者模式**：模型在后台线程生成，主线程逐块 yield。

#### **文本净化工具**

| 函数                                     | 作用                                                                              |
| ---------------------------------------- | --------------------------------------------------------------------------------- |
| `\_count\_cjk\(text\)`                 | 统计中文字符数                                                                    |
| `\_looks\_like\_mojibake\(text\)`      | 检测编码乱码（\&\#34;Ã\&\#34;, \&\#34;Â\&\#34; 等异常字节 \+ 中文字符 \&lt; 3） |
| `\_repair\_mojibake\(text\)`           | 尝试通过 latin1/cp1252 → utf\-8 重新编码修复                                     |
| `\_truncate\_at\_role\_marker\(text\)` | 正则匹配 `Human:/User:/Assistant:/System:` 并截断，防止幻觉溢出                 |

#### **chat 同步对话流程**

```Plain
chat(user_input)
    │
    ├─ 1. state.add_message(HumanMessage(user_input))
    │
    ├─ 2. assemble_final_prompt(state)  ← 四层提示词组装
    │
    ├─ 3. chat_model.invoke(prompt)     ← 模型推理
    │
    ├─ 4. state.add_message(AssistantMessage(reply))
    │
    └─ 5. return reply
```

#### **chat\_stream 流式对话流程**

```Plain
chat_stream(user_input)
    │
    ├─ 1. state.add_message(HumanMessage(user_input))
    │
    ├─ 2. assemble_final_prompt(state)
    │
    ├─ 3. for chunk in chat_model.stream(prompt):
    │       累积完整回复
    │       yield chunk
    │
    ├─ 4. state.add_message(AssistantMessage(full_reply))
    │
    └─ 5. return
```

### **Agent 状态容器（AgentState）**

```Python
@dataclass
class AgentState:
    # ── 核心状态 ──
    user: UserProfile                          # 用户画像
    messages: List[BaseMessage] = []           # 对话消息列表

    # ── 推理与规划 ──

    task_queue: List[str] = []                 # 待办任务队列
```

- **基础操作**

| 方法                                  | 说明                                        |
| ------------------------------------- | ------------------------------------------- |
| `add\_message\(message\)`           | 追加消息到 `messages` 列表末尾            |
| `get\_messages\(\)`                 | 返回完整的消息列表（有序）                  |
| `get\_last\_assistant\_message\(\)` | 反向扫描，返回最近一条 `AssistantMessage` |
| `get\_last\_human\_message\(\)`     | 反向扫描，返回最近一条 `HumanMessage`     |

| 属性                    | 说明                                         |
| ----------------------- | -------------------------------------------- |
| `human\_messages`     | 返回所有 `HumanMessage` 实例               |
| `assistant\_messages` | 返回所有 `AssistantMessage` 实例           |

| `turn\_count`         | 返回 `HumanMessage` 数量（对话轮次计数器） |

- **快照与回滚机制 save\_snapshot\(\)**

支持多步推理场景下的状态回退。当 Agent 的推理路径走偏时，可以回滚到之前的状态重新推理。

```Python
def save_snapshot(self):
    snapshot = {
        "messages": deepcopy(self.messages),
        "reasoning_process": self.reasoning_process,
        "task_queue": self.task_queue[:],
        "memory_ref": self.memory_ref,
        "is_finished": self.is_finished,
    }
    self._snapshots.append(snapshot)
```

将当前状态深拷贝后压入 `\_snapshots` 栈。

- **rollback\(\)**

```Python
def rollback(self) -> bool:
    if not self._snapshots:
        return False
    snapshot = self._snapshots.pop()
    self.messages = snapshot["messages"]
    self.reasoning_process = snapshot["reasoning_process"]
    self.task_queue = snapshot["task_queue"]
    self.memory_ref = snapshot["memory_ref"]
    self.is_finished = snapshot["is_finished"]
    return True
```

弹出最近的快照并恢复状态。返回 `True` 表示成功，`False` 表示无快照可回滚。

```Plain
正常对话流程:
    [初始状态]
        │
        ├─ add_message(HumanMessage)
        ├─ add_message(AssistantMessage)
        ├─ save_snapshot()  ← 保存检查点
        │
        ▼
    [对话进行中]
        │
        ├─ 推理成功 → 继续对话
        │
        └─ 推理失败 → rollback() → [恢复到检查点] → 重新推理
```

- **状态重置  reset\(\)**

```Python
def reset(self):
    self.messages = [m for m in self.messages if isinstance(m, SystemMessage)]
    self.reasoning_process = ""
    self.task_queue = []
    self.memory_ref = None
    self.is_finished = False
    self._snapshots = []
```

**保留**：所有 \`SystemMessage\`（系统提示词是持久的）

**清除**： 对话消息（Human、Assistant、Tool），推理过程，任务队列，记忆引用，完成标记，所有快照

### **提示词架构**

系统采用 **四层分层组装** 策略，每层职责明确、互不耦合：

```Plain
┌─────────────────────────────────────────────┐
│  Layer 1: System Base Prompt                │  身份 + 规则 + 约束
│  "你是一个专业的医疗检验助手..."              │
├─────────────────────────────────────────────┤
│  Layer 2: Task Instruction                  │  当前任务指令
│  "请根据用户的问题，结合医学知识..."          │
├─────────────────────────────────────────────┤
│  Layer 3: Context                           │  历史对话 + 工具结果
│  User: ...                                  │
│  Assistant: ...                             │
│  Tool [...]: ...                            │
├─────────────────────────────────────────────┤
│  Layer 4: Format / FewShot                  │  输出格式 + 示例
│  "请用以下格式回答：1. 说明含义..."           │
├─────────────────────────────────────────────┤
│  Assistant:                                 │  生成触发标记
└─────────────────────────────────────────────┘
```

- **实现函数 assemble\_final\_prompt\(state\)**

这是提示词组装的主入口，被 `LabAgent\.chat\(\)` 和 `LabAgent\.chat\_stream\(\)` 每轮调用。

```Python
def assemble_final_prompt(state: AgentState) -> str:
    # Layer 1: 系统提示词
    system_msg = next(
        (m for m in state.messages if isinstance(m, SystemMessage)), None
    )
    if system_msg:
        layer1 = system_msg.content
    else:
        layer1 = build_system_prompt(state.user)

    # Layer 2: 任务指令
    if state.task_queue:
        layer2 = build_task_prompt(state.task_queue[0])
    else:
        layer2 = build_task_prompt(None)

    # Layer 3: 上下文（排除 SystemMessage）
    layer3 = messages_to_prompt(
        [m for m in state.messages if not isinstance(m, SystemMessage)]
    )

    # Layer 4: 输出格式
    layer4 = build_format_prompt(None)

    # 最终组装
    return f"{layer1}\n\n{layer2}\n\n{layer3}\n\n{layer4}\n\nAssistant:"
```


### **每轮重建特性**

提示词不是一次构建后固定不变的，而是 **每轮对话都从 state 重新组装**：

- 新的 `HumanMessage` 加入 → Layer 3 更新
- 新的 `AssistantMessage` 加入 → Layer 3 更新
- `task\_queue` 变化 → Layer 2 更新
- `user` 信息变化 → Layer 1 更新

这保证了提示词始终反映最新的对话状态。

## 记忆管理

系统采用 **三层记忆架构**，对标 Hermes 智能体记忆设计思想，将记忆分为瞬时记忆、短期记忆和长期记忆三个层级，分别由不同模块承载。

```
┌─────────────────────────────────────────────────┐
│              三层记忆架构                         │
├─────────────────────────────────────────────────┤
│  瞬时记忆 (Immediate Memory)                     │
│  ─ AgentState.messages                          │
│  ─ 当前对话的完整消息列表                        │
│  ─ 每次模型推理时全部注入 prompt                  │
│  ─ 支持快照 / 回滚，防止推理走偏                 │
├─────────────────────────────────────────────────┤
│  短期记忆 (Short-term Memory)                    │
│  ─ AgentState.task_queue                        │
│  ─ AgentState.reasoning_process                 │
│  ─ 当前会话内的任务上下文与推理过程               │
│  ─ reset() 可清空（保留 SystemMessage）           │
├─────────────────────────────────────────────────┤
│  长期记忆 (Long-term Memory)                     │
│  ─ RAG 知识检索 (knowledge/)                     │
│  ─ AgentState.memory_ref（待对接）               │
│  ─ 向量化医学知识库 + FAISS 索引                 │
│  ─ Redis 缓存层（检索结果去重加速）              │
└─────────────────────────────────────────────────┘
```

### 短期记忆

#### 瞬时记忆：对话消息列表

**文件**：`python_service/harness/state/agent_state.py`

瞬时记忆由 `AgentState.messages` 承载，是 `List[BaseMessage]` 类型的有序列表，保存当前会话的全部消息。包括四种消息类型：

| 消息类型 | role | 说明 |
|---------|------|------|
| `SystemMessage` | `"system"` | 系统提示词，定义 Agent 身份和规则，会话重置时保留 |
| `HumanMessage` | `"user"` | 用户输入，每轮对话追加一条 |
| `AssistantMessage` | `"assistant"` | 模型回复，推理完成后追加 |
| `ToolMessage` | `"tool"` | 工具调用记录，含 `tool_name` 和 `tool_args` 字段（预留） |

**消息容量管理**：

瞬时记忆当前采用 **全量注入** 策略——每轮对话把所有历史消息拼入 prompt。对话框如下：

```
SystemMessage: "你是一个专业的医疗检验助手..."
    │
    ├─ HumanMessage: "我的肌酐偏高"
    │       │
    │       └─ AssistantMessage: "肌酐是肾功能的主要标志..."
    │               │
    │               └─ HumanMessage: "那饮食上要注意什么？"
    │                       │
    │                       └─ AssistantMessage: "针对肌酐偏高，饮食建议如下..."
    │
    └─ ... 持续追加
```

**全量注入的特点**：

- 优势：模型始终拥有完整上下文，不会"遗忘"早期对话
- 劣势：对话轮次增多后，prompt 长度线性增长，超出模型上下文窗口（Qwen2.5 支持 32K tokens）时会丢失最早的消息
- 后续优化方向：实现滑动窗口 + 摘要压缩——最近 N 轮保留原文，更早的消息用摘要模型压缩后注入

**快照与回滚机制**：

多步推理中，Agent 可能走偏。`save_snapshot()` 和 `rollback()` 提供状态回退能力。

```Python
# save_snapshot() 将当前状态深拷贝后压入 _snapshots 栈
def save_snapshot(self):
    snapshot = {
        "messages": deepcopy(self.messages),
        "reasoning_process": self.reasoning_process,
        "task_queue": self.task_queue[:],
        "memory_ref": self.memory_ref,
        "rag_context": self.rag_context,
        "is_finished": self.is_finished,
    }
    self._snapshots.append(snapshot)

# rollback() 弹出最近快照并恢复
def rollback(self) -> bool:
    if not self._snapshots:
        return False
    snapshot = self._snapshots.pop()
    self.messages = snapshot["messages"]
    self.reasoning_process = snapshot["reasoning_process"]
    self.task_queue = snapshot["task_queue"]
    self.memory_ref = snapshot["memory_ref"]
    self.rag_context = snapshot.get("rag_context", "")
    self.is_finished = snapshot["is_finished"]
    return True
```

```Plain Text
正常对话流程:
    [初始状态]
        │
        ├─ add_message(HumanMessage)
        ├─ add_message(AssistantMessage)
        ├─ save_snapshot()  ← 保存检查点
        │
        ▼
    [对话进行中]
        │
        ├─ 推理成功 → 继续对话
        │
        └─ 推理失败 → rollback() → [恢复到检查点] → 重新推理
```

**状态重置**：

`reset()` 方法清空瞬时记忆，但保留 `SystemMessage`（系统提示词是持久的）：

```Python
def reset(self):
    system_msgs = self.filter_by_type(SystemMessage)
    self.messages = system_msgs
    self.reasoning_process = ""
    self.task_queue = []
    self.memory_ref = None
    self.rag_context = ""
    self._snapshots = []
```

#### 短期记忆：任务上下文

短期记忆包含两个字段，用于追踪 Agent 在当前会话内的思考状态：

| 字段 | 类型 | 说明 |

**对话轮次追踪**：

`turn_count` 属性返回 `HumanMessage` 的数量，即对话轮次：


### RAG

#### 嵌入模型

**文件**：`python_service/harness/long_memory/knowledge/embedding_FAISS.py`

采用 `bce-embedding-base_v1`（由网易有道开源的 BCE 系列，专为中文检索优化），通过 `BCEFlagEmbedding` 类封装。该类实现了 LangChain 的 `Embeddings` 接口，支持两种推理后端：

| 后端 | 说明 |
|------|------|
| `SentenceTransformer` | 优先选择，简洁高效，一行 `model.encode()` 完成嵌入 |
| `transformers AutoModel` | 回退方案，当 SentenceTransformer 加载失败时使用，手动实现 mean pooling + L2 归一化 |

```Python
class BCEFlagEmbedding(Embeddings):
    def __init__(self, model_path=None, use_fp16=False):
        # 优先加载 SentenceTransformer
        self.model = SentenceTransformer(resolved_path, device=self.device)
        # 失败则回退到原生 transformers AutoModel
        self.model = AutoModel.from_pretrained(resolved_path, ...)
```

嵌入模型运行在 **CPU** 上（`RAG_EMBEDDING_DEVICE=cpu`），与 GPU 上的 LLM 推理互不抢占资源。嵌入维度为 **768**，单次编码延迟约 10-20ms。

#### 向量数据库

**文件**：`python_service/harness/long_memory/knowledge/embedding_FAISS.py`

基于 FAISS（Facebook AI Similarity Search）构建，支持两种加载路径：

```Plain Text

    │

    │       │
    │       ├─ 检查 index.faiss 是否存在
```

**文件**：`python_service/harness/long_memory/knowledge/rag_cache.py`
